# コード整理レポート — v1.0.33

## 方針
今回は「短くすること」ではなく、現在の動作を壊さず、今後の修正で追いやすい状態にすることを優先しました。
大規模なCSS統合やJavaScriptの関数再設計は、実画面ごとの回帰テストなしに行うと危険なため実施していません。

## 実施内容

### 1. 実行ファイルと運用資料を分離
ルート直下に散在していたSupabase資料・SQLを次のように整理しました。
- `docs/` : セットアップ・デプロイ・整理レポート
- `database/setup/` : 初期構築SQL
- `database/migrations/` : バージョン別migration SQL

これらはHTML/JavaScriptから読み込まれていないため、サイト実行には影響しません。

### 2. 削除済み機能のCSS残骸を除去
v1.0.32で削除した旧不具合報告ページに対応していた次のスタイルが残っていました。
- `.alpha-feedback-fab`
- `.alpha-form` / `.alpha-form-actions`
- `.alpha-report-output` / `.alpha-note`

現行HTML・JavaScriptから参照されていないことを確認して除去しました。
利用規約に残っていた「不具合報告ページ」への案内も、現在の運用に合わせて修正しています。

### 3. styles.cssの安全な重複整理
- `.workspace-footer.ego-mode .ego-footer-actions{grid-column:2}` の完全重複を1件削除
- `.detail-identity-grid` をデスクトップで6列へ再指定していた、基底ルールと同値のmedia queryを削除

CSSには過去バージョンの上書きルールがまだ多数ありますが、現在の表示を作っている可能性があるため、今回は「見た目が同一であると判断できるもの」だけを削除しました。

## あえて触らなかった箇所
- `styles.css` の過去バージョン別上書きの全面統合
- `app.js` の投稿エディター処理のファイル分割
- Supabase関連JavaScriptのAPI層再設計

これらは整理効果が大きい一方で、投稿・編集・スマホUI・既存投稿互換性に影響する可能性があります。次段階では、機能単位で分割して実画面テストを行いながら進めるのが安全です。

## 検証
- 全JavaScript: `node --check`
- 全JSON: JSONパース
- HTMLのローカルCSS/JS/画像参照: 存在確認
- 削除したCSSクラス: 現行HTML/JSに参照がないことを確認
- ZIP: 展開テスト

## 次の整理候補
1. `styles.css` を共通 / 投稿エディター / 詳細画面 / レスポンシブ補正に段階分割
2. `app.js` の投稿エディターを状態管理・描画・保存処理へ分割
3. 古いバージョンコメント単位のCSSを実画面比較しながら正式ルールへ統合

一度に大規模リファクタリングせず、各段階で公開版と表示・操作を比較する方針を推奨します。
