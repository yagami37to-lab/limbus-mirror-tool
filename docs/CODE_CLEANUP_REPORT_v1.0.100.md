# CODE CLEANUP REPORT v1.0.100

## 目的

Supabaseへの投稿保存・更新・公開後処理を投稿画面本体から分離する。

## 今回の分割

`js/post-persistence-controller.js` へ以下を移動した。

- ログイン状態の確認
- 新規投稿時の20件上限確認
- 投稿の新規保存と既存投稿の更新
- 保存エラーと完了通知
- 公開後の下書き整理と詳細画面への遷移通知

## 結果

- 投稿データの組み立てと保存処理の責務を分離
- 新規投稿と更新投稿が同じ保存経路を利用
- Supabaseのテーブル形式と投稿データ形式は変更なし

## 次の候補

第18段階では、既存投稿をURLから読み込む処理を専用コントローラーへ移し、投稿エディターの起動処理を整理する。
