# プロジェクト整理レポート — v1.0.32

## 目的
長期間の差分ZIP上書き更新で蓄積した不要ファイル・古い作業物・重複コードを確認し、現在のサイト動作を維持しながら整理しました。

## 結果サマリー
- 元プロジェクト: 約 9.22 MB / 1,106ファイル（展開後）
- 整理後: 約 1.11 MB / 54ファイル
- 約 8.1 MB、1,052ファイルを配布用プロジェクトから整理
- 容量削減の大部分は `.git/`（約7.69 MB）と、プロジェクト内に残っていた旧差分フォルダ（約0.32 MB）です。

## 今回実施した整理

### 1. 配布ZIPからGit内部データを除外
元ZIPには `.git/` が含まれており、全体容量の大部分を占めていました。Cloudflare Pages上で静的サイトを動かすためには不要なので、整理済みZIPには含めていません。

これは「Gitを使うな」という意味ではありません。ローカルでGit管理している場合は、そのリポジトリの `.git/` はそのまま保持してください。

### 2. 明確に不要な過去差分・一時ファイルを削除
- `limbus-company-strategy-site-v0.9.26-changed-files/`
- `APPLY_NOTE.txt`
- `CHANGED_FILES.txt`
- `DELETED_FILES.txt`

これらは過去の差分適用時に使われた作業物で、現在のサイトからは参照されていませんでした。

### 3. 未参照の画像・データを削除
- `assets/category-icons/story.png` — 現在のカテゴリ定義にストーリーが存在せず未参照
- `data/affiliations.json` — 空配列でコードから未参照
- `data/posts.json` — 旧サンプル投稿データ。現行はSupabase投稿を利用し未参照
- `data/site-stats.json` — 旧統計データ。現行コードから未参照
- `data/keyword-review.txt` — 開発時の確認メモでサイト表示には未使用

### 4. 旧フィードバックページを削除
`feedback.html` と `js/feedback.js` は現在どの画面からもリンクされておらず、不具合報告導線を削除した後の残骸になっていました。

### 5. app.jsの重複処理を修正
`updatePostSummaryCount()` が二重定義され、攻略タイプのボタンを押すたびに同じ `input` イベントを追加登録するコードが残っていました。外側ですでに正しいイベント登録が行われているため、内側の重複処理を削除しました。

## 削除しなかったもの
Supabase関連のセットアップ資料・migration SQLは、ブラウザ実行時には不要です。ただしDB構築履歴や再構築手順として価値があるため、今回は残しています。

また `styles.css` には過去アップデートごとの追加ルールが多く、同じセレクタが複数箇所に存在します。ただしCSSは「後ろのルールで意図的に上書きする」仕組みが多く、単純な重複削除は表示崩れにつながります。そのため今回は、機械的な大規模統合をせず現状維持を優先しました。

## 今後の整理候補
1. `styles.css` を「共通 / 投稿エディター / トップ / 詳細 / モバイル補正」の単位で段階的に分割する。
2. 過去バージョン由来のホットフィックスを、実画面テストをしながら正式ルールへ統合する。
3. `CHANGELOG.md` と公開更新履歴に存在する同一バージョンの複数エントリ（例: v1.0.25、v1.0.8）を、履歴を失わない形で統合する。
4. Supabase関連資料を `docs/`、migration SQLを `database/` へ移す場合は、別更新としてパスを明示的に整理する。

## 運用上のおすすめ
今後は「最新全体ZIP」に過去の差分ZIPや展開済み差分フォルダを入れないようにすると、再び不要物が増えるのを防げます。差分ZIPは適用後にプロジェクト外のバックアップ場所へ保管するのがおすすめです。
